# 状态机白名单只约束节点图，不约束状态数值

**背景**：本系统的招牌是"用状态机白名单约束 LLM 防止剧情跑偏"。需要钉死这个约束的精确边界：它管到哪、不管到哪。

**决定**：白名单校验只保证 AI 无法跳转到编剧未建模的节点（约束"可达节点图"）；而 flags / attributes / inventory 由 LLM 每回合通过 `stateChanges` 自由演化，引擎侧只做 clamp（如 `sanity∈[0,100]`）兜底，**不**对状态变更施加节点级白名单。被 condition 把守的闸门（如 `attr.evidence>=2`）因此可被 LLM 发放的状态满足——即 AI 改不了剧情骨架，但能左右推进节奏。

**理由**：给每个 flag/attr 变更加节点级授权会让编剧建模与引擎求值复杂度激增，而毕设场景下 LLM 作为受信任的 GM 裁判、按节点 `narrative_brief` 发放状态已经足够；把硬保证收敛在"可达节点图"这一最能体现工程价值、也最易演示与测试的维度，性价比最高。

**后果**：已知软肋——玩家凭空声称（如"我已找到凶器"）理论上可能诱导 LLM 误置 flag/发 evidence。缓解手段是在 system prompt 中明确"仅依据当前节点 `narrative_brief` 允许的线索发放状态，玩家凭空声称无效"，作为软约束，不引入引擎规则。
