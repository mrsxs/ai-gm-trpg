# 结局只经白名单跳转产生，引擎无特例死法

**背景**：基线 §7.5 提到"`sanity` 归 0 提前触发 LOSE（精神崩溃）"，但标注为"可选、非必须"。需要决定是否在引擎里实现这种**绕过节点图**的强制结局。

**决定**：不实现引擎级强制结局。一局游戏**有且只有**经白名单跳转进入 `is_ending` 节点才结束。任何"按属性触发的结局"（精神崩溃等）都由编剧建一个 `is_ending` 节点 + 在相关节点画 `attr.*` 条件出边来表达，依然走白名单。这是对规格书"可选 sanity 死法"的刻意不做。

**理由**：保持"结局是编剧的事、不是引擎特例"的纯不变量——最易演示、最易测试、答辩时一句话不打折；也避免引擎里散落 status 特判。sanity 并不浪费，它仍是可被 condition 引用的属性。

**后果**：种子剧本「迷雾古宅」当前未画 sanity 出边，故 sanity 在种子里仅为叙事氛围属性；若要"精神崩溃结局"需编剧补 `node_madness` + 出边（stretch goal）。`npc_ghost`（低语幻影）是为此预留的钩子。
