# 发布校验只保证"结构良构"，不保证"可通关"；退路是编剧约定而非强制规则

**背景**：需要划定发布校验（`ScenarioValidator.validatePublishable`）的能力边界。由于 ADR-0001（flags/attr 由 LLM 现场发放、编辑期不建模），condition 能否被满足无法静态判定。

**决定**：发布校验只做**结构良构**——有起始节点且属本剧本、非结局节点皆有出边、≥1 结局节点、分支两端合法 + condition 语法合法、从起点 BFS（纯图）可达结局。**不**试图静态保证"可通关 / 不软卡死"。防软卡死降为**编剧约定**："每个非结局节点至少留一条恒走得通的退路"（一条 `always` 出边，或像 `node_confront` 那样出边条件穷尽），**不**做成强制校验规则。

**理由**：(1) 真实可通关性取决于 LLM 是否按 `narrative_brief` 发放状态，静态测不了；(2) 想强制"退路"就得证明"一个节点的出边条件是否穷尽全部状态空间"，这是校验器做不到的（需约束求解）；(3) 退而求其次的粗规则"必须有一条 `always` 边"会**误杀** `node_confront` 这类条件穷尽（`evidence>=2` ∪ `<2`）的合法收束节点。

**后果**：剧本可能通过校验却实际赢不了 / 会软卡死——这是**已知边界**，靠 `narrative_brief` 质量与编剧约定兜，而非引擎。答辩时主动讲成"我们清楚静态校验的边界在哪、为什么不强行扩大它"。
